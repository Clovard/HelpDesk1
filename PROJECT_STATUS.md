# Угли IT HelpDesk — состояние проекта

Документ фиксирует текущую архитектуру, функции, конфигурацию и оставшиеся шаги разработки. Обновляйте его после заметных изменений.

## Назначение

Внутренняя система IT-поддержки компании «Угли IT» с русскоязычной веб-панелью, Telegram-ботом и собственной базой данных. Заявки и идеи создаются через Telegram и HelpDesk; операционная база — Cloudflare D1, а не Google Таблица.

- Последний просмотренный коммит: `fbe40c5` (`chat id`).
- Пуш и деплой выполняются владельцем через GitHub Desktop и Cloudflare.

## Технологии и размещение

- Веб-панель: React, TypeScript, Vite — `apps/web`.
- API: Cloudflare Worker на Hono — `apps/api`.
- Telegram-бот: Cloudflare Worker — `apps/bot`.
- База данных: Cloudflare D1 — `database`.
- Общие типы и конфигурация находятся в `packages`.
- Cloudflare Workers собираются/публикуются из GitHub; каждый Worker имеет собственные настройки сборки и переменные.

## Основные возможности

### HelpDesk

- Разделы заявок, идей и настроек.
- Для заявок доступны список и канбан, поиск, фильтры, карточка подробностей и редактирование.
- Статусы отображаются по-русски: «Новая», «На рассмотрении», «В работе», «Закрыта».
- Для заявки хранятся дата, время, сотрудник и Telegram ID, город, подразделение, система, тип, описание проблемы, статус, комментарий IT, уровень поддержки, ответственный и масштаб.
- Новые заявки по умолчанию получают уровень L1 и ответственного Андрея.
- Заявки можно создавать из панели вручную и через Telegram.
- Для идей хранятся сотрудник, город, подразделение, система, описание, ожидаемый результат, приоритет, статус, ответственный, комментарий и связь с заявкой.
- Для идей доступны режимы «Список / Канбан», поиск и фильтры по городу, приоритету, ответственному и статусу. Карточку идеи можно открыть нажатием на строку или карточку, редактировать и удалить; перетаскивание в канбане меняет статус через API.
- Есть экспорт заявок и идей с выбором периода в CSV.
- Список автоматически обновляет данные периодически; есть ручное обновление.
- В карточке заявки есть переписка: поддержка пишет сотруднику с сайта, сотрудник выбирает свою заявку в боте и отвечает там. История сохраняется в D1 и обновляется в панели каждые 4 секунды.
- При переводе заявки в статус «Закрыта» бот спрашивает сотрудника, решена ли проблема; подтверждение сохраняется в истории, а ответ «Нет» возвращает заявку в работу и уведомляет группу поддержки.
- В веб-панели есть отдельный раздел «Сообщения»: список диалогов показывает сотрудника, Telegram-ник, номер заявки и краткое описание; выбранный диалог открывается рядом в мессенджере.
- Для старых записей интерфейс показывает сохранённые счётчики вложений. Новые заявки и идеи из Telegram сейчас создаются без фото и файлов.

### Telegram

- Команда `/start`, меню с созданием заявки, созданием идеи и просмотром своих заявок.
- В главном меню есть понятная справка «Как пользоваться»; её также открывает команда `/help`. Справка не отменяет заполнение формы или переписку, если пользователь вызвал её во время активного действия.
- В форме заявки пользователь выбирает город, подразделение и тип, указывает систему и описывает проблему.
- В форме идеи пользователь выбирает город, подразделение и приоритет, указывает систему, описание и ожидаемый результат.
- Имя сотрудника берётся из профиля Telegram; для заявки также сохраняются username и Telegram ID, если они доступны.
- В Telegram создание заявки или идеи сейчас проходит без шага вложений; при отправке фото/файла бот сообщает, что приём временно отключён.
- После успешного создания бот отправляет сводку в рабочую Telegram-группу поддержки, без вложений.
- В разделе «Мои заявки» по умолчанию показываются активные заявки страницами по пять; закрытые доступны отдельно. После создания заявки переписка по ней открывается сразу. Ответы привязаны к Telegram ID и конкретному номеру заявки.
- Поддержка фото и файлов в Telegram временно отключена. Поля счётчиков и старая поддержка `file_id` оставлены в коде/схеме для возможного возврата позже.
- Команда `/chatid` должна ответить ID текущего чата. Реализована в коде Worker.

## Схема данных

Основные таблицы описаны в `database/schema.sql`:

- `tickets` — заявки;
- `ideas` — идеи;
- `users` — пользователи;
- `bot_sessions` — состояние пошаговых форм бота;
- `ticket_messages` — переписка по заявкам;
- `bot_ticket_chats` — выбранная сотрудником заявка для текущей переписки в боте;
- `comments`, `ticket_events` — комментарии и история событий;
- `attachments` — таблица метаданных, оставшаяся в схеме. Текущий Telegram-сценарий её не использует для хранения самих файлов.

Поля `photo_count` и `file_count` сохранены для старых данных/возможного возврата вложений. Текущее создание записей не использует эти колонки.

Миграции находятся в `database/migrations`. Миграция `0003_telegram_media_counts.sql` добавляет поля счётчиков для вложений; пока приём файлов отключён, применять её для создания заявок и идей не требуется.

## Конфигурация Telegram и Cloudflare

В `apps/bot/wrangler.toml` заданы:

- `API_URL` — адрес API;
- `SUPPORT_CHAT_ID = "-5503412304"` — ID рабочей группы SupportChat;
- D1 binding `DB`.

Секрет `BOT_TOKEN` должен задаваться в Cloudflare Worker `helpdesk-bot` как Secret. Его значение не хранится в репозитории.

Для отправки сообщений сотрудникам из карточки HelpDesk тот же `BOT_TOKEN` нужно добавить как Secret и в Worker `helpdesk-api`.

Бот добавлен в рабочую группу SupportChat. Для доступа к сообщениям пользователей из личного бота сотрудники продолжают общаться с ботом напрямую; группа предназначена для получения копий заявок/идей и вложений.

## Как внести и опубликовать изменения

1. Перед изменением базы проверьте миграции и примените каждую ещё не применённую миграцию к нужной D1-базе. Не запускайте `ALTER TABLE` повторно: D1 сообщит, что колонка уже существует.
2. Просмотрите изменения в GitHub Desktop, создайте commit и отправьте `main` в GitHub.
3. Убедитесь, что Cloudflare запустил деплой соответствующих Workers: API, бота и/или веб-панели.
4. Сначала должен быть готов API и схема D1, затем проверяйте бота и панель.
5. Не публикуйте `BOT_TOKEN`, пароли, ключи и другие секреты в коммитах, скриншотах или сообщениях.

## Известные ограничения и открытые проверки

- Пока Telegram не принимает вложения, миграция `0003_telegram_media_counts.sql` не нужна для создания заявок и идей. Перед возвратом фото/файлов проверьте её состояние в production D1.
- После добавления `/chatid` и переменной группы требуется дождаться деплоя `helpdesk-bot`; затем можно повторить `/chatid` и проверить фактическую доставку.
- После деплоя проверить создание заявки и идеи без вложений; отправка фото/документа должна дать короткое сообщение об отключённом приёме.
- Перед включением переписки примените миграцию `0004_ticket_conversations.sql` к production D1 и добавьте Secret `BOT_TOKEN` в Worker `helpdesk-api`.
- У API пока нет отдельной авторизации для сотрудников. Перед использованием переписки в production ограничьте доступ к панели и API через Cloudflare Access.
- Счётчики вложений не дают открыть/скачать файл из карточки HelpDesk. Для этого позднее понадобится отдельное файловое хранилище и API выдачи файлов.
- Настройки Cloudflare Workers могут отличаться друг от друга. Проверьте root directory, build/deploy commands и bindings отдельно для каждого Worker.
