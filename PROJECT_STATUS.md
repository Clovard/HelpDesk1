# Угли IT HelpDesk — состояние проекта

Документ фиксирует текущую архитектуру, функции, конфигурацию и оставшиеся шаги разработки. Обновляйте его после заметных изменений.

## Назначение

Внутренняя система IT-поддержки компании «Угли IT» с русскоязычной веб-панелью, Telegram-ботом и собственной базой данных. Заявки и идеи создаются через Telegram и HelpDesk; операционная база — Cloudflare D1, а не Google Таблица.

## Технологии и размещение

- Веб-панель: React, TypeScript, Vite — `apps/web`.

## Основные возможности

### HelpDesk

- Разделы заявок, идей и настроек.
- Для заявок доступны список и канбан, поиск, фильтры, карточка подробностей и редактирование.
- Статусы отображаются по-русски: «Новая», «На рассмотрении», «В работе», «Закрыта».
- Для заявки хранятся дата, время, сотрудник, Telegram ID/имя пользователя, город, подразделение, система, тип, описание проблемы, ожидаемый результат, статус, комментарий IT, уровень поддержки, ответственный и масштаб.
- Новые заявки по умолчанию получают уровень L1 и ответственного Андрея.
- Заявки можно создавать из панели вручную и через Telegram.
- Для идей хранятся сотрудник, город, подразделение, система, описание, ожидаемый результат, приоритет, статус, ответственный, комментарий и связь с заявкой.
- Есть экспорт заявок и идей с выбором периода в CSV.
- Список автоматически обновляет данные периодически; есть ручное обновление.
- В карточке заявки показывается число приложенных фото и файлов. В таблице идей есть колонка «Вложения».

### Telegram

- Команда `/start`, меню с созданием заявки, созданием идеи и просмотром своих заявок.
- В форме заявки пользователь выбирает город, подразделение и тип, указывает систему и описывает проблему.
- В форме идеи пользователь выбирает город, подразделение и приоритет, указывает систему, описание и ожидаемый результат.
- Имя сотрудника берётся из профиля Telegram; для заявки также сохраняются username и Telegram ID, если они доступны.
- При создании заявки или идеи пользователь может отправить фото/скриншоты и документы, затем подтвердить форму.
- После успешного создания бот отправляет сводку и вложения в рабочую Telegram-группу поддержки.
- Для переноса файлов в группу бот повторно использует Telegram `file_id`. В D1 записываются только количества фото и файлов; долговременной загрузки вложений в HelpDesk/R2 сейчас нет.
- Команда `/chatid` должна ответить ID текущего чата. Реализована в коде Worker.

## Схема данных

Основные таблицы описаны в `database/schema.sql`:

- `tickets` — заявки;
- `ideas` — идеи;
- `users` — пользователи;
- `bot_sessions` — состояние пошаговых форм бота;
- `comments`, `ticket_events` — комментарии и история событий;
- `attachments` — таблица метаданных, оставшаяся в схеме. Текущий Telegram-сценарий её не использует для хранения самих файлов.

Для заявок и идей в схеме предусмотрены поля `photo_count` и `file_count`.

Миграции находятся в `database/migrations`. Новая миграция `0003_telegram_media_counts.sql` добавляет эти колонки к уже созданным таблицам. Её состояние применения в рабочей D1-базе нужно проверить в Cloudflare; локальное наличие SQL-файла не означает, что миграция уже применена.

## Конфигурация Telegram и Cloudflare

В `apps/bot/wrangler.toml` заданы:

- `API_URL` — адрес API;
- `SUPPORT_CHAT_ID = "-5503412304"` — ID рабочей группы SupportChat;
- D1 binding `DB`.

Секрет `BOT_TOKEN` должен задаваться в Cloudflare Worker `helpdesk-bot` как Secret. Его значение не хранится в репозитории.

Бот добавлен в рабочую группу SupportChat. Для доступа к сообщениям пользователей из личного бота сотрудники продолжают общаться с ботом напрямую; группа предназначена для получения копий заявок/идей и вложений.

## Как внести и опубликовать изменения

1. Перед изменением базы проверьте миграции и примените каждую ещё не применённую миграцию к нужной D1-базе. Не запускайте `ALTER TABLE` повторно: D1 сообщит, что колонка уже существует.
2. Просмотрите изменения в GitHub Desktop, создайте commit и отправьте `main` в GitHub.
3. Убедитесь, что Cloudflare запустил деплой соответствующих Workers: API, бота и/или веб-панели.
4. Сначала должен быть готов API и схема D1, затем проверяйте бота и панель.
5. Не публикуйте `BOT_TOKEN`, пароли, ключи и другие секреты в коммитах, скриншотах или сообщениях.

## Известные ограничения и открытые проверки

- Не подтверждено, применена ли миграция `0003_telegram_media_counts.sql` в production D1. Это нужно проверить перед тестированием создания записей с новыми полями.
- После добавления `/chatid` и переменной группы требуется дождаться деплоя `helpdesk-bot`; затем можно повторить `/chatid` и проверить фактическую доставку.
- Нужно проверить на развернутой версии: создание заявки без вложений, заявки с фото и документом, создание идеи с вложением, наличие сводки/медиа в группе и счётчиков в HelpDesk.
- Код последних изменений не подтверждён локальной production-сборкой в этой сессии.
- Счётчики вложений не дают открыть/скачать файл из карточки HelpDesk. Для этого позднее понадобится отдельное файловое хранилище и API выдачи файлов.
- Настройки Cloudflare Workers могут отличаться друг от друга. Проверьте root directory, build/deploy commands и bindings отдельно для каждого Worker.
